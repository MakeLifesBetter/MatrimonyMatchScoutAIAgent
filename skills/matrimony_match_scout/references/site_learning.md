# Site learning (any matrimony site, no code)

Use on a site with no playbook, and to re-check a playbook after a redesign.

1. Logged-in home page: list the main navigation in plain words (matches,
   inbox/chats, interests, shortlist, search, my profile).
2. For each source the user agreed to: what one list entry shows, how the next
   page loads, how a full profile opens.
3. One full profile: where each schema field lives, including collapsed
   sections or tabs (About, Family, Partner preference, Horoscope). Note fields
   the site does not show.
4. One chat thread: how sender and messages appear, and the link back to the
   profile.
5. CALIBRATION: extract that profile, show every field (unknowns as "not
   shown"), ask "Did I read this correctly? Anything wrong or missing?".
6. Apply corrections. If a corrected value sits under a label you did not know
   (e.g. "Hometown"), remember that label for this site and note it in the checkpoint. Start the bulk scan only
   after the user confirms.
7. During the scan, if a page looks different, re-map that page type once. Three
   unreadable profiles in a row → stop, save, and tell the user in one sentence.

Record the field map in the checkpoint so a resumed run reuses it.
